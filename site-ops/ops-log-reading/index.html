日志里藏着什么，值得每周看一眼

站被挂马前两周，日志里就有陌生 PHP 文件被访问的记录。我每周一花十分钟扫日志，盯的是登录失败、404、5xx 和这些「跟平时不一样」的东西。

发布于 2026-11-23 更新于 2026-11-25 王经理网站运维实战

很多人从不看日志，等到站出问题了才翻，结果发现信号早就在里面躺了半个月。日志不是给故障收尸用的，它是提前告诉你「有东西不对」的那个东西。我没让它多复杂，每周一早上花十分钟扫一眼，看趋势和异常，不通读全文。

我最先看登录失败记录。如果一周里后台登录失败几百上千次，说明有人在暴力扫你的后台。我有个客户，日志里一周几千次失败尝试，还好密码设得够复杂没被撞开。后来我给他做了两件事：改掉默认的后台登录地址、限制同一 IP 的登录次数，第二天这种记录就基本没了。不看日志，你可能几个月都不知道有人在敲你的门。

再看 404。突然多起来的 404，两种可能：一是你改了文章或产品的网址，没做跳转，老链接全断了，搜索引擎抓过来吃一鼻子灰；二是有人在扫漏洞路径，挨个试你的目录。这两种都要处理，但方向完全不同，日志能帮你分清。我有个客户改版后发现 404 暴涨，补上几组 301 跳转，两周内就恢复了。

5xx 错误也值得盯。偶尔一两条是正常波动，成片出现就是程序在报警。我有个客户的站，日志里每天固定时间冒出一批 500，查下来是定时同步任务里的一段代码有 bug。修好之后，顺带把那个时间段的服务器负载也降下来了。

还有慢查询。数据库哪条语句跑得慢，日志里记得清清楚楚。这是我优化站速度最直接的线索——不用猜，照着它改就行。有次我照着日志给一张产品表加了个索引，页面响应直接从一秒多降到两百毫秒。

最值得说的一次，是我从日志里发现有个陌生的 PHP 文件被频繁访问，文件是我不认识的。顺着查下去，是被人传了木马进去，用来发垃圾页面。那时候站点还没被挂跳转，从外面看一切正常。早发现两周处理掉，省了后面一场大麻烦。

另外提醒一句：日志会占磁盘，别让它无限攒着。我一般设成保留三十天，老的自动清掉。前面讲过磁盘塞满导致 MySQL 停掉的案例，一半就是日志没清。看日志和清日志要一起做，只看不清，迟早把自己坑了。还有，后台登录失败如果集中在某个时间段，基本可以断定是脚本在跑——人不会一秒试十几次密码，认准这个特征处理起来就快。真撞上这种脚本，先把后台登录地址改掉，比改密码管用。

日志不难读，难的是养成看的习惯。你不用懂每一行，盯住「跟平时不一样」的地方就够了。真懒得看，至少让主机商或者运维把异常报表每周发你一份。
