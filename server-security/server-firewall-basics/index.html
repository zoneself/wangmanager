防火墙规则，最小够用就行

客户为了远程调试方便，把MySQL的3306端口对全网开放，两周内数据库被加密勒索。防火墙的原则就一句：默认全关，需要哪个开哪个，来源能限就限。安全组和系统防火墙都得设，改完还得从外网扫一遍。

发布于 2026-11-21 更新于 2026-11-25 王经理服务器与安全

有个客户跟我抱怨，说服务器一个月内被扫描了几万次，烦都烦死了。我上去一看，安全组规则是「全部端口、全部来源放行」——这是他当初为了省事设的，说这样远程访问方便。方便是真方便，攻击者也是真方便。

防火墙这事，我的原则就一句：最小够用。默认全关，需要哪个端口开哪个，来源能限就限。听着简单，但很多人反着来——默认全开，出事了再堵，永远慢一步。

一个正常的网站服务器，对公网需要开的端口其实没几个。80和443给网站，一个你自己改过的高位SSH端口给自己远程用。就这些。别的都关掉。

我印象最深的一次，是个做化工原料的客户。他为了在家调试数据库，把MySQL的3306端口对全网开放，密码还设得很简单。结果不到两周，数据库被扫到，里面客户报价单全被加密，对方留了条消息要比特币。后来数据是通过备份恢复的，停了两天，损失不小。他还在电话里跟我说「我就开了一个端口啊」。问题就在这个端口不该对全网开。

数据库、Redis、后台管理这些，本来就不该裸露在公网。真要远程访问，限来源IP——只放行你自己办公室或家里的固定IP。没有固定IP，就走SSH隧道或者VPN，别图省事直接开公网。Redis那个更典型，默认没密码，开到公网等于请人进来挖矿，我见过好几台机器CPU长期跑满，就是这么来的。

有人问出站流量要不要管。普通展示站可以不管，数据库服务器我一般限制出站——真中招了，挖矿程序要连矿池、木马要把数据传出去，出站规则一卡，就算进来了也传不走。这不是万能的，但能挡住不少低水平的攻击。后台管理目录也别留默认路径，我把 /admin、/wp-admin 这类地址改掉或者加一层访问限制，能少掉大量扫后台的机器人。

还有一层很多人忽略：云服务商的安全组和服务器系统里的防火墙，是两道独立的门。安全组在云控制台设，管的是进云之前；系统防火墙（iptables或firewalld）管的是进系统之后。两边都设上，一道配错了还有另一道兜着。我一般让客户两边规则保持一致，省得出事时不知道哪层漏了。

规则改完记得验证。我自己有个笨办法：用另一台机器，从外网扫一下自己开放的端口，看看是不是跟预想的一样。多出来的，就是漏堵的门。这个动作两分钟，但能提前发现很多问题。

防火墙不追求规则多复杂，追求的是「该开的开着，不该开的一个不放」。你要是拿不准自己安全组该怎么设，把现在放行的端口列出来发我，我帮你看看哪些该关。
