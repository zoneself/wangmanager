密码登录该关掉了

客户服务器SSH一晚上几千次失败登录，全是猜密码的。换成密钥登录，这事十分钟就能做完。我自己也踩过没验证密钥就关密码、把自己锁在外面的坑。

发布于 2026-11-21 更新于 2026-11-25 王经理服务器与安全

我有个习惯：接手一台新服务器，第一件事不是装环境，是把SSH密码登录关掉。有客户觉得我小题大做——机器又没出过事，关它干嘛。我把他服务器上的登录日志调出来给他看，他就不说话了。日志里一晚上几千次失败登录，全是猜密码的，来自几十个不同IP。他说自己密码设了十六位，我说没用——对面根本不是一条条试，是一堆IP轮着撞。

密码登录的毛病就一个字：猜。只要对面能连上你的22端口，就能无限次试。你密码设得再复杂，也架不住它一天试几万次，而且它不累、不sleep。更别说很多人图方便，密码就是公司名加年份。

密钥登录是另一回事。它是一对文件：私钥留在你自己电脑，公钥放服务器。登录时两边对一下，对得上就放行。就算攻击者把公钥看个遍，没有你那把私钥也进不来——私钥不通过网络传输，暴力破解无从下手。

我给客户配置一般就三步。在自己电脑上生成一对密钥，把公钥内容贴到服务器的 ~/.ssh/authorized_keys 里。先别急着关密码登录，开着密码、用密钥重新登一次，确认能进。确认没问题，再到 sshd_config 里把 PasswordAuthentication 改成 no，重启sshd。

中间这步「先验证再关」千万别省。我自己吃过亏。有年给一台机器改配置，密钥还没验证通过就把密码登录关了，重启sshd之后——进不去了。密钥那头我本地权限没设对，死活连不上。后来是在云服务商的网页控制台里用VNC登进去，把配置改回来才恢复。折腾了小半小时，差点以为要把机器重装。从那以后我给自己立了规矩：永远留一个能进的会话，配置改完先不动现有连接，新开一个窗口测试成功再断开旧的。

还有一个配套动作：别直接用root登录。给日常操作建一个普通用户，需要管理员权限时用sudo，再把 sshd_config 里的 PermitRootLogin 也改成 no，攻击面又小一圈。我给客户配的时候，顺手把登录日志级别调好，确保出事时能查到来源IP。

有人问，改端口、装fail2ban还需要吗？需要，但那是辅助。改22端口能挡掉无脑扫描，fail2ban能封掉反复试错的IP，它们能把噪音降下来。真正兜底的还是密钥——前面那些是让攻击者知难而退，密钥是让他根本进不来。

还有个小提醒：私钥存好，别丢。丢了就等于钥匙丢了，谁也进不去，只能走控制台重置。我让客户把私钥加密存一份在密码管理器里，别只放在一台笔记本上。换电脑、重装系统的时候最容易把私钥弄丢，这种事我碰到过两回。

关掉密码登录这事，十分钟就能做完，换来的是服务器少一大半麻烦。你要是不确定自己的密钥配得对不对，可以把步骤发我，我帮你看看有没有坑。
