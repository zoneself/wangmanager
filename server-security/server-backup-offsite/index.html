备份放在同一台服务器上，等于没备

客户服务器硬盘坏了，以为有每天自动备份，结果备份目录就在同一台机器上，一起没了。备份存在哪比备不备更关键，勒索病毒还会先把备份一起加密。

发布于 2026-11-23 更新于 2026-11-25 王经理服务器与安全

有个客户凌晨给我打电话，声音都变了：服务器硬盘坏了，网站和数据库全没了。我说你不是有备份吗？他说有，每天自动备份。我让他把备份文件找出来，找了半天——备份目录就在同一台服务器的另一块分区上，硬盘一坏，一起没了。他在电话那头沉默了很久。

这事我见过不止一次。很多人以为「做了备份」就万事大吉，其实备份放在哪，比备不备更关键。备份跟数据放在同一台机器上，机器一挂，备份跟着一起去，等于没备。

更狠的是勒索病毒。现在有些攻击进来之后，会先把你能找到的备份文件一起加密，再加密你的网站。你以为留了后手，其实后手先被废了。我有个客户就是这么中招的，网站被加密，备份目录里的压缩包也被加密，到头来只能从头重建。

我的做法是把备份送出这台机器。最省事的是对象存储，阿里云OSS、腾讯云COS这类，一个月几块钱到几十块，备份脚本每天定时把压缩包传上去。传完还能设生命周期，自动删掉太旧的，省得攒一堆。关键是那份备份跟服务器是物理隔离的——服务器彻底没了，备份还在云上。

没有云账号，至少放到另一台机器上。我有些客户有两台服务器，互相备份，或者放一台家里的小机器。再保险一点，定期把备份下载到自己电脑或移动硬盘——手动是麻烦点，但真到灾难那天，手里有份能恢复的东西，心里不慌。有几台机器互相备份的，记得定期看看对方那台是不是还活着，别等恢复时发现备份机早就停机了。

还有一件事比「存哪」更重要：备份能不能恢复。我见过太多备份，存了好几年，从没验证过，等真要用的时候发现压缩包是坏的、密码忘了、恢复脚本跑不起来。我给客户定规矩：每季度做一次恢复演练，把备份拉到一台干净机器上恢复一遍，确认网站能打开、数据库完整。没验证过的备份，别算数。

备份也别只留一份最新的。我有客户被勒索，连最新那份备份一起被加密了，幸好还留着三份历史版本，才把数据捞回来。我一般让脚本保留最近七天的每日备份、最近四周的每周备份，占不了多少空间，关键时候能救命。传到对象存储的备份再加一层加密，密钥别跟服务器放一块。

备份这事，说白了就三句话：自动做、异地存、定期验。哪一条偷懒，真出事时都要还。你现在备份存在哪、多久没恢复演练过，最好心里有个数。

要是你不确定自己的备份方案靠不靠谱，可以跟我说说现在怎么做的，我帮你挑挑里面的漏洞。
